# SPAZE – PHASE 2: GENERATIVE AI ENGINE

Act as a deep learning engineer specializing in Variational Autoencoders and generative modeling.

We are continuing the SPAZE project. Phase 1 has already created a floor-plan processing pipeline and structured room representations.

Our objective is to implement a Conditional Variational Autoencoder (CVAE) from scratch using PyTorch.

## Technology stack
- Python
- PyTorch
- NumPy
- Pandas
- Matplotlib

All libraries must be free and open source.

## Tasks

1. Design a synthetic architectural floor-plan dataset generator.
2. Generate approximately 2,000–5,000 synthetic layouts if computationally feasible.
3. Represent layouts using structured room information:
   - Room type
   - X and Y coordinates
   - Width and height
   - Orientation
   - Room adjacency
4. Generate preference labels:
   - Space-efficient
   - Open layout
   - Privacy-focused
5. Implement a Conditional VAE with:
   - Encoder
   - Mean and variance layers
   - Reparameterization trick
   - Latent space
   - Conditional decoder
6. Implement the VAE reconstruction loss and KL divergence loss.
7. Train the model using the synthetic dataset.
8. Save model weights and training history.
9. Implement inference to generate three alternative layouts from one input.
10. Allow user preferences to influence generated layouts.
11. Add a reproducible random seed and model evaluation.

## Research contribution

The core contribution is preference-controlled architectural layout generation using a Conditional VAE.

The model must generate different alternatives instead of merely copying its input.

## Evaluation

Measure:
- Reconstruction loss
- KL divergence
- Training time
- Inference time
- Layout diversity
- Geometric validity

Compare generated layouts with held-out synthetic samples.

## Integration requirements

The output must use a structured format compatible with Phase 1 and Phase 3.

Save the trained model as a .pth file.

Keep the model small enough to train on a free Google Colab GPU or a CPU fallback.

## Important restrictions

- Implement the CVAE architecture yourself.
- Do not simply download a pretrained generative model.
- Do not claim that synthetic layouts represent professional architectural designs.
- Do not rely exclusively on random coordinate generation as the final AI output.
- Explain the mathematical formulation and every important model component.

Provide complete executable code, training instructions, inference code and a sample output.

Do not proceed to Phase 3 until the model can generate and save three distinct layouts.



# SPAZE – PHASE 3: INTELLIGENT 3D GENERATION

Act as a senior Python 3D graphics and computational geometry developer.

We are continuing SPAZE. Phase 1 provides structured floor-plan data, and Phase 2 provides three generated layout alternatives from our trained Conditional VAE.

Now implement the 3D generation and visualization pipeline.

## Technology stack
- Python
- Trimesh
- Shapely
- Plotly
- NumPy
- Streamlit

All dependencies must be free and open source.

## Tasks

### A. Layout validation

1. Check room boundaries.
2. Check overlapping rooms.
3. Check room dimensions.
4. Check furniture collisions.
5. Check whether room connections are preserved.
6. Calculate a geometric constraint satisfaction score.
7. Reject or flag invalid layouts.

### B. 3D geometry generation

Convert each valid layout into 3D geometry.

Generate:
- Floor surfaces.
- Room walls.
- Interior partitions.
- Door openings or clearly represented door placements.
- Windows.
- Basic furniture such as beds, tables, sofas and chairs.

Use simple procedural geometry rather than expensive rendering systems.

### C. Interactive 3D viewer

1. Display the generated 3D building.
2. Support rotation and zoom.
3. Allow users to switch between three alternatives.
4. Use different colors for different rooms.
5. Provide an isometric viewing option.

### D. Export functionality

Implement:
- GLB 3D export.
- PNG floor-plan export.
- Download functionality through Streamlit.

### E. User experience

The user must be able to:
1. Upload a floor plan.
2. Generate alternative layouts.
3. Select an alternative.
4. Validate the layout.
5. View the corresponding 3D environment.
6. Export the model.

## Important requirements

- Preserve the actual coordinates and dimensions from the generated layouts.
- Do not use a static screenshot as the 3D output.
- The generated 3D model must be an actual editable geometric model.
- Keep the viewer lightweight.
- Handle invalid layouts gracefully.
- Reuse the existing Phase 1 and Phase 2 modules rather than rewriting them.

Provide complete executable code and explain integration between modules.

Do not proceed to Phase 4 until the entire upload-to-3D workflow works.
